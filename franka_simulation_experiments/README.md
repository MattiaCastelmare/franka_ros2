# franka_simulation_experiments

**SIM.** Closed-loop Gazebo replica of the `franka_experiments` CBF + Kalman-tracker
experiments. It runs **pipeline A unchanged** (`torque_control_stack.launch.py`:
`real_time_distance` → `cbf_safety_filter` → `qddot_to_torque` → `RtTorqueController`)
against the `franka_simulation` Gazebo plant, and adds what only a simulator can give:
**ground truth**, an emulation of the **firmware reflexes the real FR3 would have tripped**,
per-run **scoring**, a resumable **batch grid**, and a generated **report**.

**Build type**: `ament_cmake`
**Simulator**: Ignition Fortress, headless (`franka_simulation/gz_fr3_plant.launch.py`)
**Python scripts**: installed via `install(PROGRAMS … RENAME)` — no `.py` at runtime
**Pure logic**: `scripts/simexp/`, installed as `lib/franka_simulation_experiments/simexp/`
**Every number this package produces is labelled `SIM`** and lands under `sim_runs/`, never
next to hardware logs.

This package owns **no node on the safety path**. Everything that computes a torque is the
shipped hardware code, launched with `external_plant:=true`.

## 1. Why this package exists

`franka_experiments` already declares `<exec_depend>franka_simulation</exec_depend>`. Putting the
reverse edge in would make `colcon list`, `colcon graph` and `colcon build` fail for the **whole
workspace** with `Unable to order packages topologically`. So the experiment harness lives in a
**third, thin package** that depends on both and is depended on by neither
(`docs/gz_cbf_experiments_plan.md` §6, option B; H1 answered 2026-10-21).

Consequences that shape the whole design:

* nothing in `franka_experiments` or `franka_simulation` knows this package exists;
* the three default-off edits the stack needed are *arguments*, not forks:
  `external_plant:=true`, `motion_source:=none`, `experiment_logger`'s `truth_topic`;
* every derived file (controller YAML, world SDF, merged perception YAML) is **generated into the
  run directory** by the upstream generators, never hand-copied.

Two planning documents sit in the *other* package and are the authority for intent:

| file | what it is |
|---|---|
| `franka_simulation/docs/gz_cbf_experiments_plan.md` | the plan: phases, hypotheses `H1…H19`, ground rules, where the spec is wrong |
| `franka_simulation/docs/gz_cbf_experiments_report.md` | the report; its `<!-- AUTO:BEGIN/END -->` block is generated by `--report` |
| `franka_simulation/docs/sim_reference_contract/fake_hw/` | the Phase 0 ROS-graph contract the sim must reproduce |

## 3. Quickstart

Everything runs inside the container (`docker-compose.yml` mounts the repo at `/ros2_ws/src`):

```bash
docker compose up -d && docker exec -it franka_ros2 bash
cd /ros2_ws
colcon build --packages-select franka_simulation_experiments
source install/setup.bash
```

Scripts and config are **copied** at install time, so rebuild after editing them. The fast test
suite is the exception: it reads the *source* tree (`test/conftest.py` + the `../../config`
fallback in `default_path()`), so it needs no rebuild.

**One experiment:**

```bash
ros2 launch franka_simulation_experiments gz_cbf_stack.launch.py \
    condition:=kf scenario:=slow seed:=0 perception:=true
```

`condition:=` is mandatory (ground rule 3). Everything else has a defined default or comes from
the scenario. The run self-terminates after the scenario's `T` of **sim** time and prints its
directory.

**The plant alone** (Phase 1 debugging, no CBF, no perception):

```bash
ros2 launch franka_simulation_experiments gz_plant.launch.py spawn_rt_controller:=true gui:=true
```

**Just the circle, drawn in Gazebo** (no perception, no CBF, no obstacles, no logging):

```bash
ros2 launch franka_simulation_experiments gz_circle_demo.launch.py
```

The arm traces a circle in the y–z plane and `gz_trajectory_markers` draws two polylines in the
Gazebo scene itself: **red** = `P(s)`, the point the commander is asking for, **blue** = where the
end effector actually is. Both expire after `trail_seconds` (2 s, the same default and the same
`TraceBuffer` the real robot's `trajectory_overlay_node` uses), so they read as two short comets
chasing each other rather than two ever-growing scribbles; `trail_seconds:=0` keeps the whole
path. Geometry is on the command line — `center_xyz:=`, `radius:=`, `cycle_time:=`, `plane:=`.

The trail is a hard window, not a fade: `ignition.msgs.Marker` carries one `material` for the
whole strip and has no per-point colour, so the image overlay's `trail_alphas` has no equivalent
here.

The commander publishes straight onto `qddot_safe` (its own documented no-CBF wiring): with no
obstacles there is nothing to filter, and leaving `cbf_safety_filter` out keeps its rate out of
the measurement. Measured this way the EE sits **0.5 mm** from `P(s)`.

Two things it depends on. `gui:=true` (the default) is **required**: the markers are served by
Gazebo's `MarkerManager`, which is a GUI plugin, so a headless run draws nothing. And the scripts
are installed with `install(PROGRAMS)`, which **copies** even under `--symlink-install`, so an
edit to `scripts/*.py` needs `colcon build` before it runs — a new file needs
`--cmake-force-configure` as well, since `CMakeLists.txt` globs them at configure time.

**A grid**, then its report:

```bash
ros2 run franka_simulation_experiments run_gz_scenarios --grid phase5          # 302 cells
ros2 run franka_simulation_experiments run_gz_scenarios --scenarios static slow \
        --conditions kf imm --seeds 0 1 --perception true emulated             # ad hoc
ros2 run franka_simulation_experiments run_gz_scenarios --rescore --batch-dir DIR
ros2 run franka_simulation_experiments run_gz_scenarios --report  --batch-dir DIR
```

**Tests:**

```bash
cd /ros2_ws/src/franka_simulation_experiments
python3 -m pytest test -q                  # 69 fast tests, no Gazebo
python3 -m pytest test -m slow -k phase2   # one Gazebo phase (minutes)
```

## 4. Anatomy of one run

`gz_cbf_stack.launch.py` is an `OpaqueFunction`: it resolves the condition and the scenario,
**generates** the three derived files, writes `run_manifest_sim.json`, and only then builds the
launch actions. Three layers come up:

```
  ┌─ franka_simulation ─ gz_fr3_plant.launch.py ─────────────────────────────────────┐
  │  ign gazebo -s --headless-rendering   world.sdf  (generated: camera pose, D455   │
  │                                                   intrinsics, obstacle models,   │
  │    FR3 + gz_ros2_control  ◄── rt_controllers_gazebo.yaml (generated)             │
  │    ScenarioObstacles  (world plugin, PreUpdate, physics rate)                    │
  │    depth_sim_adapter   (16UC1 depth, optional range noise)                       │
  │    robot_state_publisher · joint_state_broadcaster (1 kHz)                       │
  │    joint_state_publisher (the bringup's 30 Hz republisher)                       │
  └──────────────────────────────────────────────────────────────────────────────────┘
        │ /NS_1/franka/joint_states (1 kHz)   │ depth image + camera_info
        │ /sim/truth/obstacle_poses[_vel]     │
        ▼                                     ▼
  ┌─ franka_experiments ─ torque_control_stack.launch.py (external_plant:=true) ─────┐
  │  real_time_distance ──► /cbf/per_link_distances (BEST_EFFORT)                    │
  │  commander ──────────► /NS_1/qddot_nom         (pentagon | rl | none)            │
  │  cbf_safety_filter ──► /NS_1/qddot_safe, /NS_1/cbf_status   (QP, 300 Hz)         │
  │  qddot_to_torque ────► /NS_1/torque_cmd                                          │
  │  rt_torque_controller (inside the gz controller_manager) ──► the plant            │
  │  experiment_logger (FRANKA_LOGS_DIR → <run_dir>/logger, + truth_* columns)       │
  └──────────────────────────────────────────────────────────────────────────────────┘
        ▲                                     ▲
  ┌─ this package (sim-only, passive) ────────┴──────────────────────────────────────┐
  │  episode_supervisor  /sim/episode, /sim/episode_start   (the one episode clock)  │
  │  ground_truth_node   /sim/truth/{obstacles,cp_gaps} + truth.npz                  │
  │  reflex_monitor      /sim/reflex + reflex_{trips.csv,summary.json} + RTF         │
  │  scenario_commander  /NS_1/qddot_nom   (motion:=scenario only)                   │
  │  emulated_perception /cbf/per_link_distances (perception:=emulated only)         │
  │  ros2 bag record --use-sim-time (BAG_TOPICS, no images) · pin_process            │
  └──────────────────────────────────────────────────────────────────────────────────┘
```

**Generated per run** (never shipped, always reproducible):

| file | generated by | from |
|---|---|---|
| `rt_controllers_gazebo.yaml` | `franka_experiments.utils.launch_support.generate_rt_controllers_yaml` | the hardware generator, `gazebo: true`, 1000 Hz |
| `world.sdf` | `franka_simulation/utils/gz_world.py` | the scene's template + camera extrinsics + D455 depth intrinsics + the scenario's obstacle models and the `ScenarioObstacles` plugin |
| `fr3_complete_sim.yaml` | `sim_config.perception_yaml` | `fr3_complete.yaml` ⊕ `config/sim/perception_sim.yaml` ⊕ the condition ⊕ the scenario |
| `depth_adapter.yaml` | `sim_config.depth_adapter_yaml` | `config/sim/depth_adapter.yaml` ⊕ the scenario's stage overrides (e.g. `range_noise`) |

**The episode clock.** Every node runs on `use_sim_time` (H6). The supervisor waits until the loop
really closed — `qddot_nom`, `qddot_safe`, `torque_cmd` all flowing (plus
`/cbf/per_link_distances` when perception is on) **and** `rt_torque_controller` reported `active`
by the controller manager — then `warmup_s`, then announces `t_start` **ahead** (`start_lead_s`
0.25 s + the seeded `start_offset_s`). The Gazebo obstacle plugin and the scenario commander both
switch on that single instant, so the obstacle law, the nominal law and the scoring window share
one clock. The run ends when the supervisor exits; an `OnProcessExit` handler emits `Shutdown`.

## 5. The four experiment axes

A **cell** is `scenario × condition × seed × perception`. `scene` is a fifth, usually implied.

### `condition:=` — what the barrier is allowed to know (`config/conditions.yaml`)

Three sources of defaults disagree with each other (`fr3_complete.yaml`, `fr3_control.yaml`,
`launch_defaults.yaml`; plan H12), so **no run reads any of them implicitly**. A condition is
resolved into explicit launch arguments, explicit perception keys, and a flat record for the
manifest. A key missing from the YAML is an **error**, not a default.

| condition | tracking | `obstacle_velocity_source` | IMM | prediction |
|---|---|---|---|---|
| `residual` | off | `residual` (scalar `aᵀq̇ − ḋ`) | – | – |
| `kf` | on | `tracker` (constant-velocity `KalmanTrack`) | off | off |
| `imm` | on | `tracker` | on | off |
| `imm+pred` | on | `tracker` | on | on (ballistic rows) |

The `cbf:` block mirrors `launch_defaults.yaml` (a test pins it), so the Gazebo stack runs the
flags a bare hardware launch would: `lateral_evasion`, `livelock_escape`,
`latency_compensation`, `zone_ladder`, `uncertainty_margin`, `vobs_in_hdot`,
`velocity_standoff`, the two guards, `multi_obstacle_k: 2`, ISO off. `enable_sensor_range_uncertainty`
is recorded under `cbf_yaml_only`: it is not a launch argument, so it cannot be set per run.

Three of those keys are shipped OFF and exist to be turned on per run, because they are what the
furnished `diag` scene is for — `static_scene_hold` (tell the ROOM from a body: a track whose
reported velocity has had a near-zero median for a second keeps its barrier row at full authority
and claims no velocity), `vobs_min_age_s` (how long a track id must have been SEEN before its
velocity is trusted) and `vobs_floor_min_frames` (consecutive frames the residual floor must
persist before it may overrule a track). Watch `stat=`, `young=` and `fhold=` in `CBFDIAG`.

Per-run overrides go through `set:=` (launch) or `--set` semantics in the batch (`sets={...}`):

```bash
ros2 launch … condition:=kf set:='vobs_in_hdot=false;imm_enabled=true'
```

Overrides are validated: an unknown key, or `obstacle_velocity_source:=tracker` without
`obstacle_tracking`, or a perception/flag disagreement, all raise.

### `scenario:=` — 75 names in `config/scenarios.yaml`

Positions are offsets from the flange at `Q0`, exactly as `cbf_scenarios.scenarios()` writes them;
`test_scenario_catalog.py` imports the Python definitions and checks this file against them number
for number. **Do not edit one without the other.**

| family | count | what |
|---|---|---|
| `catalog` | 11 | the 1:1 port: `static`, `around`, `static_noisy`, `approach_hold`, `slow`, `slow_noisy`, `fast`, `fast_seen_early`, `ball`, `ball_slow`, `wedge` |
| `pentagon` | 7 | the circular task with obstacles on its path: `pentagon_{clear,on_path,beside_path,crossing,pursuer}`, plus two repeated-encounter scenarios: `pentagon_sweeping` (one ball sweeping through the path, 12 passes in 30 s, one track identity) and `pentagon_crossing_train` (5 balls 0.75 m apart, a pass every ~2.1 s, a new identity each time) |
| throws | 53 | the `approach_envelope.py` speed sweep (`throw_{a,b,c<L>}_v<v>`, 8 speeds) + 5 `throw_ballistic_v<v>` (gravity, aimed to hit the flange) |
| `tests` | 4 | perception/plugin test scenes, not experiments: `p3_robot_only`, `p3_static`, `p3_moving`, `p4_laws` |

Obstacle laws, evaluated **by the Gazebo plugin at the physics rate** (and restated in
`simexp/obstacle_laws.py` for the truth checks): `static`, `linear`, `ballistic` and `oscillate`
(closed form, no integrator), `pursuit` (explicit Euler toward the TRUE flange, i.e.
`cbf_scenarios.Sphere.step`). `oscillate` is `p(t) = p0 + axis * amplitude * sin(2 pi t / period)`,
so `p0` is both the start and the mid-point of the sweep, crossed twice per period at the peak
speed `amplitude * 2 pi / period`.
Obstacles are **visual-only**: the depth camera sees them, the arm cannot collide with them, and
contact is measured geometrically from truth.

Two episode rules are enforced at resolve time: obstacles are **parked** at `z = −20 m` before the
start (a birth at `p0`, never a teleport), and `enforce_start_clearance` pushes any obstacle that
starts *inside* the barrier just outside it, recording the shift in `start_shift` (`wedge` starts
9 mm inside `d_safe` with the real control-point set, because the catalog numbers were written for
`cbf_scenarios`' coarser emulated set).

### `seed:=`

Seed 0 is the **1:1 port**: `start_offset_s = 0` and no jitter. For other seeds the only randomness
is the start phase within one camera frame (`U[0, 1/90 s]`) plus the depth adapter's noise seed,
unless a scenario declares `jitter_m`.

### `perception:=` — the three columns

| value | what publishes `/cbf/per_link_distances` |
|---|---|
| `true` | the full chain: simulated D455 → `depth_sim_adapter` → **unchanged** `real_time_distance` |
| `emulated` | `emulated_perception`: `cbf_scenarios`' emulation from truth, through the real message constructor |
| `false` | nobody. The filter runs box-only — useful for plant debugging, not for experiments |

### `scene:=` — which lab (`sim_config.SCENES`)

`rig` · `bare` · `diag` · `diag_bare`. Each one names a world template, a camera extrinsics file
and a depth intrinsics file. The lab was rearranged and the camera moved between the two
recordings, so the numbers are **never shared**: `rig` is the lab of `rosbag/irim1_raw`, `diag` the
DIAG robotics lab of `datasets/experiments_irim2.zip`. `*_bare` is the same camera over an empty
floor (H9). The world generator and `real_time_distance` are handed the **same** extrinsics file,
so they can never disagree.

**`diag` is the default** (`sim_config.DEFAULT_SCENE`): every run that does not name a scene is
built in the DIAG lab, **furniture included** — the robot's table, the right-hand desk with its
monitor and laptop, the second cell's bench and the back wall, all measured from
`datasets/experiments_irim2.zip`. The depth chain therefore sees the room, exactly as it does on
the robot, and the barrier is built on what it reports. `rig` and `bare` stay selectable so a run
recorded in the old lab can be re-launched on the lab it came from.

The scenes that must be an empty floor still ask for one explicitly: the Phase 3 / Phase 4 test
scenes in `config/scenarios.yaml` (`p3_*`, `p4_laws`) and `test_phase2_closed_loop` keep
`scene: bare`, the **rig** camera, because their sphere placements were derived from that camera's
rays (`sim_config.DEFAULT_BARE_SCENE` is `diag_bare` for anything new that wants the DIAG camera
over bare floor).

## 6. The sim-only nodes

All passive: they publish diagnostics and truth, and command nothing. All of them map joint names
to indices **by name** (`{n: i for i, n in enumerate(msg.name)}`) — never by position.

### `episode_supervisor`
Owns the episode. Waits for the closed loop (see §4), publishes `/sim/episode = [state, t_start,
t_now]` at 50 Hz (0 waiting, 1 running, 2 done) and `/sim/episode_start`, ends the run after
`duration_s` of sim time (0 = until stopped). On finalise it writes the episode window, reflex
verdict, RTF and git provenance into `run_manifest_sim.json`, stamps `experiment_logger`'s own
`run_manifest.json` with `plant: gazebo` / `SIM: true`, and **checks
`franka_experiments/franka_logs`**: anything that appeared there during the run is a SIM output in
a hardware directory, so it is moved to `<run_dir>/stray_logs` and the run is flagged.

### `ground_truth_node`
On every 1 kHz joint state it computes the control points `real_time_distance` uses — the same
function, `utils.distance_utils.define_control_points`, with the same config — but from **forward
kinematics of the true joint state** instead of TF. Then the true signed surface gap to every
sphere, `‖cp − c‖ − r_obs − r_cp`, *unclamped* (negative = penetration).
Publishes `/sim/truth/obstacles` and `/sim/truth/cp_gaps` at 100 Hz, and accumulates every 1 kHz
sample into `truth.npz` (flushed every 5 s and at exit).

### `reflex_monitor`
Gazebo has no velocity reflex, no position reflex and no torque-rate limiter, so a sim run can
"pass" where the robot would have stopped with red lights. This replays the firmware checks on
every 1 kHz sample, with the robot's own limits imported rather than restated:

* **velocity** — `cbf_hard_limits.fr3_velocity_envelope(q, margin=1.0)`, libfranka's
  position-dependent curve, + a 1e-3 rad/s tolerance;
* **position** — the mechanical limits;
* **torque** — `|τ|` against the 87/12 N·m effort limits, on the JSB effort field
  (= `τ_cmd + g_KDL(q)`, measured in Phase 1);
* **torque rate** — `|dτ_user/dt| > 1000 N·m/s`, with `τ_user = effort − g(q)` from Pinocchio at
  `g = 9.8`. On this robot `franka_hardware` leaves libfranka's rate limiter **on**, so the command
  is *clipped*, not aborted. These ticks are counted as `torque_rate_clipped` — **not** trips, but
  a fidelity gap: Gazebo executed a torque the robot would have smoothed. (The spec called this a
  trip; the code says otherwise — plan §2 H5.)

Any trip ⇒ `FAIL`. It also measures the **RTF** from `/clock` vs monotonic time.

### `scenario_commander`
Replaces the pentagon commander when `motion:=scenario` (the stack runs `motion_source:=none`).
The two nominal laws of `cbf_scenarios.run_scenario` are inline there and cannot be imported, so
`simexp/scenario_laws.py` restates them term for term and `test_scenario_laws.py` **executes the
exact source lines extracted from `cbf_scenarios`** and demands bit-equal results:

```
joint PD    q̈ = −12 (q − goal) − 2√12 q̇
Cartesian   a  = 25 e + 10 (v_ref − v),  J⁺ = Jᵀ(J Jᵀ + 0.05² I)⁻¹
            q̈ = J⁺(a − J̇ q̇) − 6 (I − J⁺J) q̇
```

Runs at 300 Hz (one evaluation per QP tick) and holds `Q0` with the same PD before the episode,
which also removes the few-mrad sag Gazebo leaves at spawn.

### `emulated_perception`
The middle column: Gazebo plant + the whole stack, but camera, distance engine and tracker replaced
by what `cbf_scenarios` feeds its filter. True gap clamped at 0 (no dilation margin, no depth
noise, no field of view), normal = `unit(cp − centre)`, one track per obstacle with `frames_seen`
from first sight, velocity = truth + `N(0, 0.02)` per axis, `vel_cov = 0.05² I`, delivered
`t_cam = 13 ms` after capture and **stamped with the capture time**. The messages are built by the
real constructor (`perception_msgs.build_cp_messages`); only the track fields are written here. One
timer at the frame rate — a 1 kHz publisher cost the QP loop CPU it does not cost on hardware.

### `pin_process`
`filter_cpu:=N` pins `cbf_safety_filter` (all threads) to a CPU, the sim counterpart of the robot's
`rt_pin_cpu`. It only touches a process carrying **this** launch's `IGN_PARTITION`, so a second sim
on the host is never affected. Measured on this host at load ~20, same stack: **245 Hz unpinned vs
300 Hz pinned**.

## 8. The batch runner

`run_gz_scenarios` (`simexp/batch.py`). **Every cell is a fresh headless Gazebo**, started and torn
down by process group, so no state crosses from one cell to the next — there is no reset to verify.

* **cell name** → `<scenario>__<condition>[-key=value…]__<gz|emul|noperc>__s<seed>`, a safe path
  component (`+` → `P`);
* **teardown** (`simexp/procs.py`): `setsid`, then SIGINT → SIGTERM → SIGKILL on the group, then a
  sweep that kills anything still carrying this run's `IGN_PARTITION`. An orphaned Gazebo keeps
  publishing `/clock` into the next run, which is why this is belt and braces. `leftovers()` is
  what the tests assert on;
* **resume**: a cell with a `cell_result.json` is not re-run;
* **`cells.csv`** is rebuilt from **every** cell directory after each cell, so several grids can
  share one batch directory and a partial batch is already a full table. Written via a temp file +
  `os.replace`;
* `ok = not timed_out and not leftovers and min_h is not None`;
* each row carries `SIM=True`, the RTF and the **achieved QP rate in sim time**.

Predefined grids:

| `--grid` | cells | what |
|---|---|---|
| `phase5` | 302 | seed 0 of everything first; catalog × 4 conditions (full chain) + × 2 (emulated); pentagon + ballistic throws for seeds 0–1; the `throw_a` sweep at seed 0 |
| `emulated30` | 22 | catalog × {`residual`,`kf`} at `cbf_scenarios`' own 30 fps — isolates the *plant* difference against column 1 |
| `flags` | 21 | `kf` with each track-consuming flag (`vobs_in_hdot`, `uncertainty_margin`, `latency_compensation`) off in turn, on the 7 moving-obstacle scenarios |

`--rescore` re-runs the three scorers on every cell of a batch, in a process pool, **without
Gazebo** — the move after a scoring fix. `--report` writes the tables.

## 9. Scoring

Three scorers run right after a cell ends (and on `--rescore`).

### `closed_loop.summarize_run` — always
Everything is measured **inside the episode window** `[t_start_sim, t_end_sim]`:

* `min_h`, `min_gap`, `neg_duration_s`, `contact`, `min_h_cp`, `t_min_h` — from the **true** 1 kHz
  per-CP gaps (`h = gap − d_safe`, `contact = gap < 0`), with the real CP set and radii;
* `task_final_err` / `task_done` — `‖q(t_end) − goal‖ < 0.05 rad`;
* `jerk_p50/p99/max` — `‖Δq̈_safe‖/Δt` over consecutive `/NS_1/qddot_safe` messages;
* `slack_max` per family (`obs/sc/qlim/sing/cap/spd`) from the throttled `CBFDIAG` lines (a
  *sampled* maximum) and `slack_max_any` from `/NS_1/cbf_status` at every QP tick;
* `fallback_levels` — QP ticks at `full`/`box-only`/`brake`, as the difference of the filter's
  cumulative `fb=[…]` counter across the window (100-tick resolution); `livelock_escapes`;
* `rows_rate_hz`, `rows_latency_ms_p50/p95` — bag receipt minus capture stamp of
  `/cbf/per_link_distances` (the perception hop `latency_budget.py` cannot measure here: it needs
  depth images in the bag); `capage_ms_*` — the CBF's own sensing age at the QP;
* `rtf`, `rtf_p10`, `reflex_verdict`, `reflex_trips`, `rate_clips`, `qp_rate_hz`, `fault_ticks`,
  `controller_active_at_start`, and the pentagon tracking error when there is one.

### `estimator_metrics.score_run` — obstacles + a perception that publishes rows
Estimator vs truth, with `compare_vobs.py`'s own definitions (its functions are *imported*, not
reimplemented). Per CP and per frame: `v_true = n̂ᵀv_obs` of the sphere the entry's point lies on
(within `r + 0.05 m`), `v_trk` from the message's track, and `v_res` from the **shipped** residual
estimator called on its own code with its real call-site arguments. Reported: lag (positive =
leads), bias, RMS per CP with ≥ 30 samples plus `pooled_*` over all CPs, the noise floor on
`compare_vobs`' static windows, `confirm_ms` / `trust_ms`, track identity (`n_ids`, `id_switches`),
and σ calibration (share of `|v_trk − v_true| ≤ kσ`, against 0.683/0.954/0.997).

### `attribution.attribute_run` — moving obstacles
Writes the truth in the format `ball_throw_eval.py score --truth` reads and runs **the shipped
scorer as a subprocess** on the run's bag; its pass table then goes to
`approach_probe.cmd_causes`, which labels every pass with the first of four causes (not in rows /
untracked / velocity untrusted / too late) or `ok`. One classification-preserving adaptation:
`approach_probe`'s regex silently drops a *negative* lead, so negative leads are rewritten to
`0ms` (a lead is only used via `isfinite` and `< need_ms`, where 0 and any negative give the same
answer).

## 10. The three-column comparison and the report

The point of the whole package is to separate **plant** from **perception**:

| column | plant | perception |
|---|---|---|
| 1 `off` | `cbf_scenarios.py` double integrator | its own emulation, 30 fps (shipped) and 60 fps |
| 2 `emul` | **Gazebo + the whole stack** | the same emulation (`emulated_perception`), 30 and 90 fps |
| 3 `full` | **Gazebo + the whole stack** | simulated D455 → `real_time_distance` → tracker |

`off@30 → emul@30` is the **plant** difference (same perception rate); `emul@90 → full` is the
**perception** difference (same plant). `simexp/offline.py` runs column 1 with the Gazebo
conditions' flags forced onto the offline filter, including the two guards the stack maps onto
thresholds — `cbf_scenarios`' own `shipped_params` would otherwise take only five flags from
`launch_defaults` and the rest from `fr3_control.yaml`.

Column 1 is capped at 60 fps for a reason worth knowing: `cbf_scenarios` keeps **one frame in
flight**, so with `t_cam = 13 ms` it delivers nothing above `1/0.013 = 77` fps — at 90 fps
`last_msg` stays `None`, there are no rows, no barrier, and `min_h ≈ −0.25 m` in every scenario.

`--report` regenerates **only** the text between `<!-- AUTO:BEGIN -->` and `<!-- AUTO:END -->` in
`franka_simulation/docs/gz_cbf_experiments_report.md`; findings, proposals and deviations outside
the markers are hand-written and kept. Tables A–G: run quality, estimator vs truth, tracks,
closed loop, the three columns, pentagon, throws, and the flag cross when the batch has one.
Medians with `[min, max]` across seeds; booleans as `k/N`. The offline column is cached in
`<batch>/offline.json`.

## 12. Tests

`pytest.ini` deselects `slow` by default, so `python3 -m pytest test` is **69 fast tests, no
Gazebo**. What they actually pin is the interesting part — most of them assert the port against the
*original code*, not against a copy of its numbers:

* `test_scenario_laws.py` extracts the exact source lines from `cbf_scenarios.py` and requires
  bit-equal results;
* `test_scenario_catalog.py` re-runs `approach_envelope.cell` with `run_scenario` captured and
  checks every expanded throw against it, pins the pentagon path to `fr3_control.yaml`, and
  verifies no scenario starts inside the barrier;
* `test_conditions.py` pins the `cbf:` block to `launch_defaults.yaml`;
* `test_sim_config.py` pins the sim extrinsics to the real calibration, the world's depth sensor
  to the D455 FOV/resolution, that the two labs never share a calibration, and that run
  directories never land in `franka_logs`;
* `test_reflex_checks.py` pins the limits to the robot's and that a torque rate is a clip, not a
  trip — including that a *sample gap* is not misread as one;
* `test_emulation.py`, `test_estimator_metrics.py`, `test_offline_and_attribution.py`,
  `test_closed_loop.py`, `test_batch.py`, `test_analysis.py` cover the rest.

The five opt-in Gazebo phases (`-m slow`, minutes each):

| phase | what it proves |
|---|---|
| 1 | `τ_cmd = 0` at `Q0` drifts < 1 mrad over 10 s (H3: the plugin adds `g_KDL(q)`); the effort field *is* the applied torque; a `q̈` step is tracked through the shipped `qddot_to_torque` + `RtTorqueController` |
| 2 | the full chain with perception, no obstacles: the shipped digests run unchanged, pentagon p95 < 2 cm (measured 4.3 mm; 46 cm before armature, H19), zero reflex trips |
| 3 | the simulated D455 through the **unchanged** `real_time_distance`: reported gap = true gap − the engine's 12 px dilation margin (`m_px·Z/fx`), `|median| ≤ 1 cm`; robot-only scene has no obstacle rows (H9); a moving sphere gets a confirmed track with the right velocity |
| 4 | the obstacle plugin holds each analytic law to 1e-6 m and the pursuit to 2 mm; parked before the start, born at `p0` without a teleport; the logger carries finite `truth_*` columns |
| 5 | one cell through the batch runner: emulated rows arrive at the frame rate and each equals the true gap at its capture stamp to 1 mm; the controller was active at episode start; `cells.csv` and the report build |

`test/launch/launch_test_graph_contract.py` is **not** collected by pytest:

```bash
ROS_DOMAIN_ID=77 launch_test src/franka_simulation_experiments/test/launch/launch_test_graph_contract.py
```

It diffs the live graph against `sim_reference_contract/fake_hw` on the safety path (same nodes,
same topic types, same endpoint reliability/durability, same TF tree) and checks rates **in sim
time** against the hardware numbers — a wall-time count would scale with the host's RTF instead of
measuring the stack (196 Hz at RTF ~0.9 for the same stack that reads 298 Hz at RTF 1).

## 13. Critical notes

**Ground rules this package will not bend.**
`condition:=` is required and resolves with no implicit defaults (a missing key raises). Every
output is labelled `SIM` and goes under `sim_runs/` — the supervisor actively hunts for SIM output
that leaked into `franka_experiments/franka_logs` and moves it out. `sim_runs/` is git-ignored and
lives in the *source* tree so it is visible on the host through the container mount;
`$FRANKA_SIM_RUNS_DIR` overrides it.

**Rates must be counted in sim time.** Every node runs on `use_sim_time`. A wall-clock rate
measures the host's load, not the stack. This is why `qp_rate_hz` is `len(status)/(t1−t0)` in sim
seconds and why the RTF is reported next to it.

**`truth.npz` is not really 1 kHz.** It is *written* per joint-state sample, but under load the
measured grid is **448–688 Hz with gaps up to 207 ms**. Any derivative taken from it is unreliable
at that resolution. Set the CPU governor to `performance` before a batch; treat finite differences
on `truth.npz` with suspicion.

**`NO_DATA` has no consumer.** `reflex_monitor` correctly reports `NO_DATA` instead of `PASS` when
it saw less than 90 % of the expected samples (a starved monitor, not a clean run), but nothing
downstream distinguishes it: `batch`'s `ok` ignores the verdict entirely, and the report's "reflex
PASS" column simply does not count it. A starved monitor therefore reads as a quality dip, not as
an explicit diagnosis. (The fix for this lived on a branch that was deleted on 2026-10-28.)

**Joint order.** On the real robot `/NS_1/franka/joint_states` is published as
`[j1, j3, j6, j7, j2, j4, j5]`. Every node here maps by **name**; keep it that way, or Jacobians
silently decorrelate.

**The QP needs its solver pinned.** `qpsolvers==4.3.3` with `osqp<1.0`. Otherwise
`available_solvers == []` and the filter dies with `SolverNotFound` — the stack never comes up and
every cell times out.

**Threads.** The passive sim nodes (all but the supervisor) are launched with
`OPENBLAS_NUM_THREADS=1` and `OMP_NUM_THREADS=1` on purpose: an unbounded BLAS in a passive monitor steals the QP's cores. Do not remove it. Avoid
raising `SCHED_FIFO` on a Python thread in this stack — it throttles the node through the GIL
rather than protecting it.

**Obstacles cannot touch the arm.** They are visual-only (no `<collision>`, gravity off), so
`contact` is a geometric statement about truth, never a physics event. A "collision" in a SIM
number means `gap < 0`.

**`config/conditions.d/` is inert.** `conditions.py` reads `config/conditions.yaml` and nothing
else; the directory and its `mppi_it08.yaml` are a leftover of deleted work (its `shaper:` keys
have no implementation in this tree). It is untracked — delete it or ignore it, but do not expect
`--conditions mppi_it08` to resolve.

**Old runs can name scenes that no longer exist.** `sim_runs/20261024/…` carries
`"scene": "irim2"`, since renamed to `diag`. Re-scoring such a run is fine (the scene is only
provenance); re-*launching* it with that name now raises.

**`gz_cbf_stack`'s actions are deliberately not in a scoped `GroupAction`.** The stack starts nodes
from `TimerAction`s, which fire after a group's scope has been popped; they would then lose both
`use_sim_time` and `FRANKA_LOGS_DIR`, and the logger measurably wrote into
`franka_experiments/franka_logs`, next to hardware runs.
